## Контекст: що нам РЕАЛЬНО потрібно (і що — НІ)

Цей застосунок — **портфоліо + лід-форма одного експерта**, а не платформа з багатьма майстрами. Тому з усього бекенду Уроку 12 нам потрібен **один-єдиний сценарій**:

> Клієнт тисне «Відправити заявку» → заявка **зберігається в базу** + **миттєво падає Оксані в Telegram** → клієнт бачить «Заявку отримано».

**НЕ робимо** (це з прикладу-каталогу, нам не треба):
- ❌ Мульти-бот / мульти-майстер SaaS (Крок 3 уроку) — у нас один експерт, не платформа
- ❌ CRUD каталогу послуг, картки майстрів, портфоліо з бази (контент захардкоджений у фронті — і це ок)
- ❌ Слоти / розклад / бронювання часу
- ❌ Оплата всередині застосунку
- ❌ **VPS і бот 24/7** (Блок 4 уроку) — наша задача це коротка API-функція, її чудово тягне Vercel. VPS потрібен лише боту, що сам шле нагадування; ми цього не робимо.

## 1. Які дані зберігаємо

### Таблиця `leads` (заявки)
| Поле | Тип | Опис |
|------|-----|------|
| `id` | uuid (pk) | автоген |
| `created_at` | timestamptz | автоген, `now()` |
| `name` | text | імʼя з форми |
| `contact` | text | Telegram/Instagram @username з форми |
| `tier` | text | обраний тариф (`basic`/`standard`/`vip`/—) |
| `message` | text | «про себе» (необовʼязково) |
| `tg_user_id` | bigint | id юзера Telegram (з перевіреного initData) |
| `tg_username` | text | @username юзера |
| `source` | text | звідки прийшов (напр. `mini_app`) |

SQL уже готовий — файл `supabase-schema.sql` поряд.

---

## 2. Які API потрібні

Один ендпоінт — serverless-функція на Vercel:

### `POST /api/lead`
1. **Валідує `initData`** (перевірка підпису `hash` секретом = токен бота) — щоб дані були справді з Telegram, а не підроблені.
2. Дістає `tg_user_id`, `tg_username` з перевіреного `initData`.
3. **Вставляє рядок** у Supabase `leads` (через service-key, лише на сервері).
4. **Шле заявку Оксані** через Bot API `sendMessage` (її `chat_id`).
5. Повертає `{ ok: true }`.

Більше ендпоінтів не треба: каталог не читаємо з бази (він у фронті).

---

## 3. Хто що бачить і редагує

- **Клієнт (фронт):** лише відправляє заявку через `/api/lead`. Напряму з базою **не** працює.
- **Сервер (API):** єдиний, хто пише в базу (service-key тільки в env Vercel).
- **Оксана:** бачить заявки двома шляхами — (1) повідомлення в Telegram від бота, (2) таблиця `leads` у дашборді Supabase (як Google-таблиця).
- **Supabase RLS:** увімкнено, публічного доступу немає. Лише сервер через service-key.

## 4. Ключі та змінні (.env / Vercel env — НІКОЛИ не в git, не в чат)

| Змінна | Де взяти | Призначення |
|--------|----------|-------------|
| `BOT_TOKEN` | BotFather (вже є) | валідація initData + sendMessage |
| `SUPABASE_URL` | Supabase → Project Settings → API | адреса бази |
| `SUPABASE_SERVICE_KEY` | там же (`service_role`) | запис у базу (**тільки на сервері!**) |
| `OKSANA_CHAT_ID` | свій numeric id (напр. через @userinfobot) | куди слати заявку |

На Vercel: **Project → Settings → Environment Variables** (не в код, не в клієнт).

## 5. Зміни у фронті (коли бекенд буде готовий)

Поточний `submitForm` (буфер + відкрити личку) → замінити на:
```js
await fetch('/api/lead', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ initData: tg.initData, lead: { name, contact, tier, message } })
});
// показати екран успіху (app НЕ закривається, нічого вставляти вручну не треба)
```
